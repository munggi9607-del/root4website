# RootKit 화면 (신규)

담당: 혜린
상태: 브리프 작성 중
메뉴 이름: 2026-11-25 Community → **RootKit**으로 바뀜. 주소 `/rootkit/`, 레일에서 Archive 아래.

> 시안에는 이 화면이 없습니다(Community 자리의 "준비 중" 다이얼로그뿐). 아래 **고정**은 디자인시스템이 정한 것, **제안**은 담당자가 바꿔도 되는 출발점입니다. 제안을 정하면 리드에게 확인받습니다.

## 1. 이 화면은 무엇인가

**고정:** ROOT4가 자체적으로 만든 디자인시스템을 **어떻게 활용하는지** 소개하는 페이지입니다. 토큰·컴포넌트 목록을 늘어놓는 문서가 아니라, "이 시스템으로 이렇게 만든다"를 보여 줍니다.

제안: 읽는 사람은 디자인시스템을 처음 보는 외부 사람(고객, 지원자)과 새로 온 팀원입니다. 다 읽고 나면 "ROOT4는 정해진 규칙 위에서 빠르게, 일관되게 만든다"는 인상을 받습니다.

## 2. 핵심 행동

제안: 활용 사례 하나를 열어 "규칙 → 결과 화면"을 확인한다. (담당자가 정해서 확인받기)

## 3. 본문 배치

**고정:** B. 읽는 페이지.

## 4. 섹션 구성

| 순서 | 섹션 | 컴포넌트 | 내용 |
|---|---|---|---|
| 1 | 머리 | PageHead hero | **고정** 아이브로우 `ROOT4 / ROOTKIT`. 제목은 두 줄 문장(제안: `같은 규칙 위에서,<br>더 빨리 만듭니다.`) |
| 2 | 무엇이 들어 있나 | PageHead section + Card panel 3열 | 제안: 토큰(색·글자·간격) / 컴포넌트 / 화면 틀 세 덩어리를 한 줄 설명과 함께 |
| 3 | 활용 흐름 | PageHead section + 번호 단계 | 제안: `01 / 규칙 읽기` → `02 / 브리프 쓰기` → `03 / 화면 만들기` → `04 / 합치기` (README 작업 순서를 사람 말로) |
| 4 | 활용 사례 | Chip filter + Card panel 그리드 | 제안: 이 사이트의 실제 메뉴(Projects, Archive 등)를 사례로. 카드에 "쓴 컴포넌트·토큰"을 칩으로 |
| 5 | 끝 | Button outline 또는 Composer | 제안: `디자인시스템 문서 보기` 또는 `함께 만들고 싶은 경험을 알려주세요` — 둘 중 하나만 |

## 5. 적용할 규칙

- PageHead hero는 하나, 화면 맨 위
- 카드 variant는 panel 하나로 통일
- 토큰 이름·값을 보여 줄 때도 글자는 최소 11px, 색 견본은 `tokens.css` 변수에서 가져옴(값을 직접 적지 않음)
- 주 버튼은 화면에 하나

## 6. 규칙에 없어서 정해야 하는 것 (담당자가 채우고 보고)

- 색 견본(스와치), 코드 조각 블록, 전후 비교(시안 → 규칙) 같은 표현이 필요한가 → 필요하면 새 컴포넌트로 보고
- 사례 카드를 누르면 해당 메뉴로 보낼지(`data-route`), Dialog로 설명할지

## 7. 규칙과 부딪힐 수 있는 것

- 디자인시스템을 소개하려면 보라 말고 다른 색(팔레트 전체)을 보여 줘야 할 수 있음 → 견본 안에서만 쓰고, 화면 강조색은 보라 하나 유지. 애매하면 보고.
- Archive(포스팅)와 내용이 겹치지 않게: 시스템 만든 과정 이야기는 Archive 글로, RootKit은 "활용법"만.

## 8. 빈 상태 · 오류 · 로딩

- 걸러 본 결과가 없을 때: 카드 자리에 `body-md` `--text-secondary` 한 줄 + `전체 보기` Button ghost

## 9. 모바일

- 카드 3열 → 1열, 필터 칩은 줄바꿈, 단계는 세로로
