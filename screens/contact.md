# Contact 화면 (신규, 모달 → 독립 페이지)

담당: 병하
상태: 브리프 작성 중

> 시안의 Contact는 다이얼로그(`#contact-modal`)입니다. 이번에 독립 화면으로 만듭니다. 시안 문구와 구성은 그대로 가져옵니다.

## 1. 이 화면은 무엇인가

프로젝트를 함께 하고 싶은 사람이 고민을 적어 남기는 곳입니다.

## 2. 핵심 행동

프로젝트 메모를 쓰고 저장한다. (시안: 텍스트 파일로 저장, 외부 전송 없음)

## 3. 본문 배치

**고정:** C. 집중 페이지.

## 4. 섹션 구성

| 순서 | 섹션 | 컴포넌트 | 내용 (시안 문구) |
|---|---|---|---|
| 1 | 머리 | PageHead hero | `LET'S START A CONVERSATION` / `다음 경험을<br>함께 만들어요.` / `기획부터 디자인, 구축과 운영까지.<br>어떤 고민에서 시작하는지 들려주세요.` |
| 2 | 관심 분야 | Chip filter (여럿 선택) | 제안: `브랜드 리뉴얼` · `앱 · 플랫폼 구축` · `AI 서비스 기획` (Projects 제안 칩과 같은 말) |
| 3 | 메모 | TextField | placeholder `프로젝트 아이디어를 적어보세요.` |
| 4 | 저장 | Button primary | `프로젝트 메모 저장 ↓` |
| 5 | 도움말 | label-sm `--text-tertiary` | `작성한 내용은 텍스트 파일로 저장됩니다. 외부로 전송되지 않습니다.` |

## 5. 적용할 규칙

- 주 버튼은 저장 하나. 시안의 ghost 저장 버튼은 이 화면의 핵심 행동이라 primary로 올립니다.
- TextField는 라벨을 화면에 보입니다(`프로젝트 메모`).
- 헤더 `Contact Us ↗`와 레일 Contact 모두 이 화면으로 옵니다.

## 6. 규칙에 없어서 정해야 하는 것

- 이름·이메일 칸이 필요한가 → 외부 전송이 없으므로 시안에는 없음. 넣으려면 보고.
- 저장 완료 알림 → 알림 컴포넌트 없음. 보고.

## 7. 규칙과 부딪힐 수 있는 것

- 메모가 비었을 때 오류 표시 → 오류 색 정의 없음. 우선 저장 버튼 disabled로 처리.

## 8. 모바일

- 한 단 그대로, 저장 버튼 폭 100%.
