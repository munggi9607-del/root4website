# 프로젝트 상세 만들기 가이드

담당: 명지
적용: `/projects/detail/?p=번호` (화면 틀 [D. 쇼케이스](00-화면-틀.md) — GNB 없음, 프로젝트 고유색)
상태: 2026-11-25 규칙 확정. 지금 20개 상세는 임시 템플릿(같은 목차 5개)이고, **프로젝트 내용을 받는 대로 이 가이드에 따라 하나씩 바꿉니다.**

사용자가 프로젝트 하나의 **비주얼과 설명글**을 주면, 그 내용에 맞는 **목차**를 정하고 아래 **블록**을 골라 쌓아 상세페이지를 만듭니다. 목차와 구성은 프로젝트마다 달라도 됩니다.

---

## 1. 받는 것 (입력)

| 항목 | 필수 | 메모 |
|---|---|---|
| 프로젝트 이름, 한 줄 설명 | 필수 | 대표 제목과 보드 카드에 씁니다 |
| 분류 | 필수 | Brand / Digital / Service |
| 설명글 | 필수 | 길어도 됩니다. 목차를 나누는 기준이 됩니다 |
| 비주얼 | 필수 | 여러 장. 순서와 "이건 크게" 같은 지시가 있으면 따릅니다 |
| 정보 | 선택 | 고객사, 연도, 기간, 역할(기획·디자인·개발), 링크 |
| 고유색 | 선택 | 없으면 대표 비주얼에서 뽑습니다(4번) |

빠진 필수 항목이 있으면 만들기 전에 묻습니다. 설명글을 지어내지 않습니다. 문장을 다듬거나 나누는 것은 되지만, 받은 내용에 없는 사실(수치, 고객 반응 등)을 더하지 않습니다.

## 2. 목차 정하기

- **4–7개.** 받은 설명글의 흐름을 따라 나눕니다. 항목 하나 = 본문 섹션 하나.
- **처음은 `OVERVIEW`, 끝은 `NEXT`로 고정.** 가운데는 프로젝트마다 다릅니다.
- 이름은 **영어 대문자 한두 단어**. 번호 `01`부터.
- 가운데 항목 예시 (골라 쓰거나 내용에 맞게 새로):

| 프로젝트 성격 | 가운데 목차 예 |
|---|---|
| 브랜드 | `CONCEPT` `IDENTITY` `COLOR` `TYPOGRAPHY` `APPLICATIONS` |
| 디지털 | `CHALLENGE` `RESEARCH` `FLOW` `INTERFACE` `INTERACTION` |
| 서비스 | `PROBLEM` `INSIGHT` `JOURNEY` `TOUCHPOINTS` `OUTCOME` |
| 공통 | `PROCESS` `VISUAL` `FINAL SYSTEM` `RESULT` |

- 섹션 하나에 내용이 너무 적으면(문단 1개 + 비주얼 없음) 앞뒤 섹션에 합칩니다.

## 3. 블록 (섹션 안에 쌓는 조각)

이미 만들어 둔 조각만 씁니다. 새 조각이 필요하면 멈추고 보고합니다.

| 블록 | 모양 | 언제 | 패럴렉스 |
|---|---|---|---|
| `overview` | 대표 제목(display-lg) + 한 줄 설명 │ 대표 비주얼, 아래 소개 제목·문단·정보 | **OVERVIEW에만, 반드시 하나** | 작게 |
| `text` | 제목(heading-lg) + 문단, 넓으면 2단 | 설명이 중심일 때 | 없음 |
| `scene` | 비주얼 7 : 글 5, 좌우 번갈아 | 비주얼 한 장 + 설명 한 덩어리 | 작게 |
| `gallery` | 비주얼 2–3장 그리드 | 같은 무게의 비주얼 여러 장 | 작게 |
| `quote` | 흐린 비주얼 배경 위 한 문장(display-md) | 핵심 메시지 한 줄 | 작게 |
| `stage` | **스크롤 고정 확대**: 카드 크기 → 화면 가로·세로 전체 | 가장 보여 주고 싶은 비주얼 | **최대화** |
| `full` | 본문 폭을 넘어 목차 오른쪽 전체를 쓰는 비주얼 한 장, 천천히 움직임 | 넓은 비주얼(가로형 결과물, 공간 사진) | **최대화** |
| `next` | 다음 프로젝트 카드(그 프로젝트 색) + 버튼 | **NEXT에만, 반드시 하나** | 없음 |

- **작게** = 비주얼이 틀 안에서 천천히 움직이는 정도(속도 0.1–0.2). 글은 0.05 이하.
- 주요 문구(대표 제목, 섹션 제목, quote, stage 설명)는 영역에 들어오면 한 글자씩 나타납니다. 본문 문단은 그대로.

## 4. 비주얼 최대화 영역 — 한 페이지에 1–2곳

`stage`·`full` 블록이 **비주얼을 화면 가로·세로 가득 채워 보여 주는 영역**입니다.

- **한 페이지에 1곳 이상, 2곳 이하.** 3곳 이상이면 지루하고 무거워집니다.
- **고르는 기준:** 프로젝트의 결과를 가장 잘 보여 주는 비주얼, 사용자가 "크게"라고 지정한 비주얼, 해상도가 가장 높은 비주얼 순.
- **위치:** OVERVIEW 바로 다음에는 두지 않습니다(첫 화면에 이미 대표 비주얼이 있음). 2곳이면 서로 붙이지 않고 사이에 섹션 하나 이상을 둡니다. 보통 가운데쯤 한 곳, 끝(NEXT 앞) 한 곳.
- **해상도:** 화면 전체를 채우므로 가로 **1600px 이상**을 권장합니다. 그보다 작으면 흐려질 수 있다고 보고하고, 사용자가 괜찮다면 씁니다.
- `stage`는 스크롤 약 3화면 동안 고정되므로, 한 페이지에서 `stage`는 **최대 1개**. 두 번째 최대화 영역은 `full`로 합니다.
- 동작 줄이기(`prefers-reduced-motion`)면 고정·확대 없이 다 덮은 장면 한 장으로 보입니다.

## 5. 색

- 바탕 `color`, 글자 `text`를 `projects/projects-data.js`에 적습니다.
- 사용자가 고유색을 주면 그 색을 씁니다. 단, 채도가 높아 눈이 피곤한 원색이면 **채도 42% 이하·밝기 34–44%**로 눌러 쓰고, 원래 색과 바꾼 색을 같이 보고합니다.
- 고유색이 없으면 대표 비주얼의 대표색에서 뽑습니다.
- 글자색은 바탕과 대비 **4.5:1 이상**(검정 `#141414` 또는 흰색 중 대비가 큰 쪽).

## 6. 작업 순서

1. 받은 내용을 읽고 **보고**합니다. 코드는 아직 쓰지 않습니다.
   - 목차안 (번호·이름·각 섹션에 들어갈 글·비주얼)
   - 섹션별 블록
   - 최대화 영역 1–2곳과 고른 이유
   - 고유색 (받은 색 / 뽑은 색, 대비 값)
   - 받은 내용에서 빠진 것, 해상도가 낮은 비주얼
2. 사용자가 확인하면 비주얼을 `projects/assets/{프로젝트-이름}/`에 넣고, `projects-data.js`에 그 프로젝트의 목차·블록을 적습니다.
3. 로컬에서 확인합니다: 데스크톱·모바일, 목차 이동과 현재 위치 표시, 최대화 영역, 동작 줄이기, 11px 미만 글자 없음, 가로 스크롤 없음.
4. 이 문서 맨 아래 "만든 프로젝트" 표에 한 줄 추가합니다.

## 7. 데이터 모양 (첫 프로젝트를 받을 때 구현)

지금 `detail.js`는 모든 프로젝트를 같은 임시 목차로 그립니다. 첫 실제 프로젝트를 받으면 아래처럼 프로젝트마다 `detail`을 적고, `detail`이 있는 프로젝트는 그대로 그리게 바꿉니다(없으면 지금 임시 템플릿).

```js
{
  no: "02", label: "Profile study", type: "Brand", caption: "…",
  color: "#e8e3e4", text: "#141414",
  detail: {
    meta: { client: "…", year: "2026", role: "기획 · 디자인 · 개발" },
    sections: [
      { id: "overview", label: "Overview", blocks: [{ type: "overview", image: "profile/cover.jpg", title: "…", body: "…" }] },
      { id: "identity", label: "Identity", blocks: [
        { type: "scene", image: "profile/logo.jpg", title: "…", body: "…" },
        { type: "stage", image: "profile/hero-wide.jpg", side: ["profile/a.jpg", "profile/b.jpg"], caption: "…" }
      ]},
      { id: "color", label: "Color", blocks: [{ type: "gallery", images: ["…", "…", "…"] }] },
      { id: "next", label: "Next", blocks: [{ type: "next" }] }
    ]
  }
}
```

목차는 `sections`의 순서와 `label`에서 자동으로 만들어집니다.
